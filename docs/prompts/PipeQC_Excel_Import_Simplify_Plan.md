## Зачем

Цель — упростить. На экране импорта спулинга (`/spooling/import`) плитка «Excel / CSV» сейчас показывает
две кнопки скачивания, строку «Шаблон» с «Сохранить как шаблон», четыре поля «Выбрать файл» (стыки,
материалы, фланцы, опоры), редактор «Сопоставить колонки» и кнопку «Проверить файлы». Человеку нужно другое:
скачать наш шаблон, перенести в него свои данные и загрузить его обратно. Сейчас одну и ту же книгу
приходится выбирать до четырёх раз, а если выбрать её только в «Стыках», заполненные листы материалов,
фланцев и опор молча не попадают в импорт.

Второе: по списку ошибок после проверки нельзя найти место в Excel. Номера строк не совпадают с Excel,
одна и та же причина повторяется на каждой строке, серверные ошибки приходят по-английски.

## Решено владельцем (не переобсуждать)

**Плитка Excel**

- Плитка называется «Excel» (`BUILT_IN_TEMPLATES` в `modules/engineering/domain/import-template.ts:87`).
- В блоке ровно две кнопки:
  - «Скачать шаблон Excel» — та же книга, что сейчас (`spooling-template.xlsx`: листы `weld`, `trace`,
    `bolt`, `supp`, «Справка», «Коды проекта»);
  - «Загрузить заполненный шаблон» — одно поле, принимает только `.xlsx`.
- Из книги читаются все листы `weld`, `trace`, `bolt`, `supp`, какие в ней есть. Лист `weld` обязателен.
  Книга без него не загружается, и на экране появляется сообщение: в книге нет листа `weld`, скачайте
  шаблон и перенесите данные в него. Остальные листы — по желанию.
- Проверка запускается сама, как только выбран файл. Отдельной кнопки «Проверить файлы» нет. Если в листе
  нет обязательной колонки, задание не создаётся: на экране сообщение с именем колонки и советом скачать
  шаблон.
- На сервер книга уходит один раз, под ролью `weld`. Строки всех листов собирает браузер, как сейчас.
- Из этого блока убираем: кнопку «Скачать шаблон CSV», приём `.csv`, `.txt` и `.xls`, четыре поля,
  строку «Шаблон» с «Сохранить как шаблон», редактор «Сопоставить колонки». Свой реестр в его собственном
  виде больше не загружается — только через наш шаблон. Это осознанно.
- Блок «Решения по ревизиям» и кнопка «Применить импорт» остаются как есть.
- Плитки SpoolGen (четыре файла) и PCF ведут себя как раньше. Строка «Шаблон» нужна PCF и там остаётся.
- Сервер и база не меняются, миграций нет. Сохранённые в проектах шаблоны таблиц (`source = 'table'`,
  например «UPG таблица 21.10» в UPG-1) не трогаем: экран их просто больше не читает.

**Список ошибок**

- Место указывается так, как его видно в Excel: «Лист weld, строка 7». Номер строки — тот, что Excel
  показывает слева, с учётом строки заголовков и пустых строк.
- Одна запись на одну причину. В заголовке — причина и значение («Зоны PDS «A-200» нет в проекте»), под
  ним лист, колонка (заголовок из шаблона, например `PDS_AREA`) и строки диапазонами: «строки 2–41, 45».
- Какие строки показывать:
  - ошибка изометрии (зона PDS, класс, линия, разные значения внутри изометрии) — все строки листа `weld`
    этой изометрии;
  - ошибка катушки — строки этой катушки;
  - ошибка стыка, материала, фланца или опоры — его строка.
- У каждого серверного кода есть текст на русском и английском. Значения для текста берутся из строки,
  на которую указывает ошибка.
- Одна проблема не показывается дважды. Браузер и сервер сейчас находят одно и то же под разными кодами:
  `ORPHAN_SPOOL` и `SRV_ORPHAN_SPOOL`, `ISO_MIXED_LINE` и `SRV_ISO_MIXED_LINE`, `ISO_MIXED_SERVICE_CLASS`
  и `SRV_ISO_MIXED_SERVICE_CLASS`.
- Сначала ошибки, потом предупреждения. Над списком одна строка итога: либо «N ошибок — исправьте файл и
  загрузите его снова», либо «Ошибок нет — проверьте изменения ниже и примените импорт».
- Файл со списком ошибок не делаем.
- Список общий для всех плиток (`modules/imports/ui/import-issue-list.tsx`). На SpoolGen и PCF он не
  должен стать хуже. Если то же решение бесплатно даёт им правильные строки и русские тексты — хорошо,
  но отдельно этого не добиваться.

## Что уже есть (прочитай, не угадывай)

- Экран: `modules/engineering/ui/spooling-import.tsx`, `table-import-panel.tsx` (обслуживает и Excel/CSV,
  и SpoolGen), `import-template-download.tsx`, `import-template-sheets.ts`, `column-mapping-editor.tsx`,
  `import-template-bar.tsx`. Отправка: `modules/engineering/infrastructure/submit-spooling-import.ts`.
- Чтение книги: `readSheetMatrix` в `modules/imports/infrastructure/xlsx-workbook.ts:35`. Она передаёт
  `blankrows: false`, и номер строки Excel теряется на первой же пустой строке. Ещё её читают справочные
  импорты (`modules/imports`), их поведение менять нельзя.
- **Две нумерации в одной колонке.** В `import_job_issues.row_number` лежат номера двух видов:
  - замечания браузера (`parseSpoolgenMatrix` в `modules/engineering/domain/parsers/spoolgen-parser.ts`,
    `cross-file.ts`) несут `record.lineNumber` — индекс строки данных после заголовка (1 = первая строка
    данных, то есть строка 2 в Excel без пустых строк);
  - серверные (`SRV_*`) несут номер строки задания из `buildStagingRows`
    (`modules/engineering/domain/definition.ts`): сначала все изометрии, потом катушки, стыки, опоры,
    фланцы, материалы. С местом в Excel он не связан. Например, ошибка зоны PDS приходит на строку
    изометрии, то есть «Строка 1».
  `rawValues` строки задания — это значения записи, без номера исходной строки и без листа.
- Ошибки видны только сразу после проверки: они хранятся в состоянии `spooling-import.tsx`, а история
  импорта их не показывает. Поэтому соответствие «строка задания → лист и строки Excel» можно держать в
  памяти браузера, отправленные строки при этом не меняются.
- Серверные коды, которые может выдать проверка спулинга:
  - базовая проверка (`supabase/migrations/20260803092000_spooling_import_apply.sql:593` и дальше):
    `SRV_PDS_MISSING`, `SRV_SERVICE_CLASS_MISSING`, `SRV_WELD_TYPE_MISSING`, `SRV_THICKNESS_MISSING`,
    `SRV_NDE_MATRIX_MISSING`, `SRV_WPS_MISSING` (предупреждение), `SRV_ISO_MIXED_LINE`,
    `SRV_ISO_MIXED_SERVICE_CLASS`, `SRV_ORPHAN_SPOOL`;
  - обёртка (`20261021100000_spooling_thickness_frozen_at_validation.sql`): `SRV_SPOOLING_SPINE_MISSING`,
    `SRV_SPOOLING_JOB_TOO_LARGE` и второй вариант `SRV_THICKNESS_MISSING` («правило добавили после
    проверки, проверьте ещё раз»).
  Сообщения у них английские. `describeSpoolgenIssue` (`modules/engineering/ui/spoolgen-issue-text.ts`)
  переводит только `SPOOLGEN_ISSUE_CODES` (`modules/engineering/domain/spoolgen-issue.ts`), остальное
  показывает как есть.
- Проверка, что шаблон и импорт согласованы:
  `modules/engineering/application/import-template-roundtrip.test.ts`. Образцы и их README:
  `fixtures/import-samples/` (CSV-образец `table/weld-register-cp1251.csv` проверяет путь с сопоставлением
  колонок).

## Что решить в плане

1. **Как сохранить номера строк Excel при чтении**, не меняя `readSheetMatrix` для справочных импортов.
   Учесть пустые строки внутри данных и то, что лист может начинаться не с `A1`.
2. **Как устроено соответствие** «замечание → лист, колонка, строки Excel» для обеих нумераций, где оно
   живёт и как по нему группируются записи.
3. **Тексты для каждого серверного кода.** Отдельно решить:
   - как различить два варианта `SRV_THICKNESS_MISSING`, не разбирая английское сообщение;
   - что писать для `SRV_SPOOLING_JOB_TOO_LARGE`, если лимит знает только сервер.
4. **Как разделить `table-import-panel.tsx`**: простая панель для Excel и прежнее поведение для SpoolGen.
   Без флагов и веток, которые нужны только «на всякий случай».
5. **Что удалить.** Правило: удаляем то, чем пользовался только путь Excel/CSV с сопоставлением
   (редактор колонок, функции черновиков сопоставления в `application/import-table.ts`, CSV-шаблон,
   ставшие лишними тексты в `messages/*/spooling.json`, CSV-образец с его проверками и раздел README).
   Оставляем то, чем пользуются SpoolGen и PCF. По каждому удаляемому имени — доказательство через `grep`,
   что больше его никто не вызывает.

## Правила проекта (из CLAUDE.md, обязательны)

- Все строки, которые читает человек, — только в `messages/en/*.json` и `messages/ru/*.json`, термины по
  `docs/i18n/glossary-ru.md`. Проверка `npm run test:unit` ловит литералы в экранах и пропуски в русском файле.
- Сервер решает правило и причину, клиент переводит код в слова. Правило в TypeScript заново не выводить.
- Без новых зависимостей, без миграций.
- Живой локальный стенд не сбрасывать: не запускать `demo:prepare`, `demo:showcase`, `supabase db reset`,
  `npm run verify`, `npm run test:db`.
- Работать в текущей папке и ветке, без новых веток. В рабочем дереве есть чужие незакоммиченные файлы
  (`scripts/upg/*`, `modules/home/*`, `messages/*/home.json`), их в коммиты не добавлять.

## Готово, когда

1. На плитке «Excel» ровно две кнопки. Скачанная книга, заполненная по строке-примеру, загружается одним
   выбором файла и проходит без ошибок, со всеми четырьмя листами. Тест roundtrip переписан под одну книгу.
2. Тесты:
   - книга с пустой строкой между данными и с ошибкой в строке после неё → в списке номер строки Excel;
   - серверная ошибка на изометрии → все строки `weld` этой изометрии, собранные в диапазоны;
   - книга без листа `weld` → сообщение, задание не создаётся;
   - у каждого кода из списка выше есть текст на русском и английском;
   - одна проблема от браузера и от сервера показывается один раз.
3. `npm run test:unit`, `npm run typecheck`, `npm run lint` зелёные.
4. Проверено в браузере на локальном стенде, **только в проекте UPG-1**. Проверка теперь создаёт задание
   сразу при выборе файла, поэтому в `TRACK01-A`, `TRACK01-B` и `SHOWCASE-1` файлы не выбирать вообще.
   Порядок:
   - загрузить шаблон, заполненный по примеру → ошибок нет, ниже видна новая изометрия;
   - загрузить книгу с несуществующей зоной PDS в двух строках и пустой строкой между данными → номера
     строк в списке совпадают с Excel;
   - ничего не применять, созданные задания отменить в истории импорта.
5. Коммиты на текущей ветке, только свои файлы. В конце открой экран импорта UPG-1 на локальном стенде в
   браузере и покажи мне результат.
