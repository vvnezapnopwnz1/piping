## Зачем

На экране импорта спулинга (`/spooling/import`) человек выбирает плитку источника: AVEVA E3D / PDMS,
Smart 3D / CADWorx, Plant 3D, Excel / CSV, SpoolGen. Он должен иметь возможность скачать шаблон или
образец для своей плитки и сравнить со своим файлом до загрузки или заполнить данными шаблон и после загрузить в нашу систему: какие колонки и ключевые слова мы
читаем, что обязательно, в каких единицах, какие коды есть в проекте.

## Решено владельцем (не переобсуждать)

| Плитка                    | Что скачивается                                                                                                                                                                                                                                                                                 |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Excel / CSV               | XLSX: заголовки, которые импорт узнаёт без сопоставления, одна строка-пример, лист «Справка» (обязательность, единицы — диаметр в дюймах, толщина в мм, допустимые значения цех/монтаж, откуда берётся), лист «Коды проекта» (активные зоны PDS, классы, типы стыков из `loadImportReferences`) |
| Excel / CSV               | CSV в UTF-8 с BOM и разделителем `;` — как вариант для тех, кто работает в CSV                                                                                                                                                                                                                  |
| SpoolGen                  | Четыре TXT с табуляцией (`weld.txt`, `trace.txt`, `bolt.txt`, `supp.txt`)                                                                                                                                                                                                                       |
| AVEVA, Smart 3D, Plant 3D | Образец PCF (не шаблон для заполнения: PCF выгружает CAD) плюс короткий список того, что мы читаем из PCF (`UNITS-BORE`, `PIPELINE-REFERENCE`, `PIPING-SPEC`, `REVISION`, блоки `WELD` с `SKEY`/`CATEGORY`/`REPEAT-WELD-IDENTIFIER`/`WELD-TYPE`, `SPOOL-IDENTIFIER`)                            |

Не делаем: ZIP-архив (нет зависимости — новые не добавляем), XLS/ODS, выпадающие списки в ячейках
Excel (в бесплатном SheetJS их нет — коды идут отдельным листом).

## Что решить в плане

1. Книга XLSX — одна на роль или одна книга с листами по ролям. Сейчас импорт читает только первый лист
   (`readFirstSheetMatrix`). Если одна книга, план должен включать выбор листа по роли при загрузке
   и тест на это; если по книге на роль — четыре кнопки или одна с меню.
2. Откуда берётся образец PCF для скачивания: статический файл из `fixtures/` (тогда как он попадает
   в сборку — `public/` или импорт как текст) или собирается в коде. Образец не должен расходиться с
   тем, что читает `modules/engineering/domain/pcf-welds.ts`: нужен тест, что скачиваемый образец
   проходит `buildPcfSubmission` без ошибок.
3. Шаблон и импорт должны оставаться согласованными: тест «скачанный шаблон, заполненный строкой-примером,
   проходит `buildTableSubmission` / `buildSpoolgenSubmission` без ошибок и без ручного сопоставления».
4. Заголовки шаблона: канонические (`ISO_NUMBER`…) или русские синонимы — выбрать и обосновать.
   Если русские, учесть, что диаметр по русскому заголовку не сопоставляется автоматически
   (`ДУ`/`Диаметр` — миллиметры).

## Правила проекта (из CLAUDE.md, обязательны)

- Все строки, которые читает человек, — только в `messages/en/*.json` и `messages/ru/*.json`, термины
  по `docs/i18n/glossary-ru.md`. Названия продуктов на плитках берутся из `BUILT_IN_TEMPLATES`.
- Чтение — обычные select, правила остаются на сервере, клиент правило не выводит.
- Без новых зависимостей. Без миграций, если они не нужны.
- Живой локальный стенд не сбрасывать: не запускать `demo:prepare`, `demo:showcase`, `supabase db reset`,
  `npm run verify`, `npm run test:db`. pgTAP, если понадобится, — `bash tasks/material-check/pgtap.sh`.
- Работать в текущей папке и ветке, без новых веток. В рабочем дереве могут быть чужие незакоммиченные
  файлы — не добавлять их в коммиты.

## Готово, когда

На каждой плитке есть кнопка скачивания в своём формате; скачанный файл, заполненный по примеру,
загружается обратно без ошибок и без ручного сопоставления; тексты на русском и английском; проверено
в браузере на локальном стенде (без нажатия «Проверить файлы» в проектах TRACK01-A/B и SHOWCASE-1).
