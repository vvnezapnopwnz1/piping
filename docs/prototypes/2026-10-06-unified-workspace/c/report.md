# Отчёт по реализации концепции C (Object Workbench)

## Модель взаимодействия и компоновка
Концепция C построена вокруг идеи **рабочей среды объекта (Workbench)**, где идентификатор объекта (Spool или Test Pack) является главной связующей сущностью. 
Вместо изолированных списков для разных стадий (Материалы, Сварка, Инспекция), пользователь всегда видит выбранный объект в центре с контекстной навигацией по его жизненному циклу (вкладки операций). Справа находится шкала готовности, где отображаются реальные зависимости и блокировки, а слева — очередь на обработку (например, фильтруемый список спулов с указанием Stage/Location/NDE/PWHT). 

## Преимущества и tradeoffs
**Преимущества:**
* **Максимальный контекст:** Пользователь понимает состояние объекта целиком. При отбраковке NDE сразу видно, как это повлияет на RFT. Не нужно переключаться между разными изолированными "dashboard".
* **Снижение когнитивной нагрузки:** Вместо прыжков по глобальным разделам с потерей фильтров, оператор двигается по операциям одного объекта.
* **Единый layout:** Экраны Spool и Test Pack работают по одному паттерну (List -> Focus -> State).
* **Глубокие ссылки:** Полное сохранение контекста (`project`, `view`, `spoolId`, `tpId`) в History API позволяет навигации Back/Forward работать предсказуемо и возвращать пользователя к конкретному объекту.

**Tradeoffs:**
* Чуть меньше места для таблиц, так как экран разделен на три колонки (List, Object, Timeline) на десктопе. Это компенсируется складыванием панелей в одну колонку на узких экранах (mobile 390px).
* Требуется более продуманное управление локальным состоянием, чтобы поиск в боковой панели не перерисовывал весь экран со сбросом форм.

## Сделанные взаимодействия и сценарии (включая доработки)
* **Глобальная навигация и История:** Единый реестр `NAV`. Использование `pushState` сохраняет в `history.state` контекст выбранного объекта и проекта, что делает кнопки Back/Forward полностью функциональными.
* **Ролевая модель:** Реализован переключатель `QC Engineer` / `Reader`. В режиме Reader элементы управления (input, select) отключаются (`disabled`), скрываются кнопки сохранения, и появляется информационный баннер о режиме "только чтение". Навигация при этом остается доступной.
* **Overview:** Добавлена полная идентичность (название проекта, владелец, контракт). Внедрены 3 карточки "Attention Required" (вместо голой таблицы), обеспечивающие прямой переход в нужный контекст (например, прямиком к NDE спула SP-1001-A). Корректно отображаются обновляемые локальные счетчики (85 всего, 63 recorded, 19 issued).
* **Проекты:** Реализованы семантические кнопки `Open Project`, индикатор `Current Project` и `Return to current project`. Пустой проект P-207 явно показывает "Empty Project", что визуально отличается от пустого результата поиска ("No matches"). Смена проекта очищает поиск и выбранные объекты.
* **Fabrication:** Заменен placeholder на реальную вкладку с таблицей fabrication evidence (Fit-up, Welding) и информацией об инспекторах.
* **Поиск:** Фильтрация по `SP-` и `ISO` реально фильтрует левый сайдбар (обновляя только его, не стирая данные в центральной панели). Введен явный паттерн "Clear search". Вводимые пользователем строки экранируются (`escapeHTML`) при выводе на экран ("No matches found for ...").
* **Material Check:** Трассировочные коды больше не используют `autofill` — форма запоминает ровно те значения, что ввел пользователь, и при "Simulate Save" состояние пересчитывается без магии.
* **NDE:** Форма усилена — добавлены `Examination Date` (с ассоциированным label) и обязательный `Outcome`. При `Rejected` требуется `Defect Code`. При `Accepted` локальные счетчики (Total/Recorded/Issued) и состояние NDE успешно обновляются.
* **Test Pack:** Принятие NDE переводит TP в `Ready for blinding`. Дальнейшие шаги (Blinding, Pressure Test) последовательно открываются и физически изменяют локальное состояние. 
* **Контекстная помощь:** При клике на "Help" открывается всплывающее окно `coach mark`, указывающее на реальный контрол текущего экрана. Помощь закрывается по `Esc` и запоминает отказ от подсказок в `localStorage` (с уникальным ключом для прототипа C).
* **CSS и Доступность:** Исправлена проблема специфичности CSS (`.workbench {display: grid}`), из-за которой пустые рабочие области просвечивали поверх `overview`. Добавлена полная поддержка фокуса с клавиатуры (`Enter`/`Space`) для всех интерактивных элементов (`[role="button"]`). Поддерживается мобильная верстка (без overflow).

## Созданные файлы
* `index.html` — единая структура Workbench, переключение через атрибут `data-view`.
* `styles.css` — CSS Grid layout, исправленная специфика, дизайн-токены (цвета, сетка, typography).
* `app.js` — управление состоянием (mock DB, view routing, role selector, coach marks, simulated saves, history API).
* `report.md` — этот отчёт.

## Обновления по фидбеку (Финальные правки)
* **Overview:** Обновлены счетчики: 16 spools (4 Laydown, 25%), 1 RFT Achieved, с корректными метками NDE. В списках добавлено примечание "6 illustrative rows from 16".
* **Help:** Tooltip привязывается к элементам только в активном экране (например, по ID или data-target), не перекрывая навигацию. Включен clamp в пределах видимой области (viewport) и логика открытия/закрытия без сброса введенных данных.
* **Empty States:** Улучшено различие между результатами поиска и пустыми проектами, поля поиска теперь очищаются при смене проекта.
* **Simulations & Validation:** Валидация материалов требует заполнения всех полей (100% trace codes). Кнопки переименованы в `Simulate ...`, таймауты перерисовки (setTimeout) убраны в пользу мгновенной обратной связи, сохранения NDE (Accepted) стали идемпотентными (не крутят счетчики дважды). Запись Rejected не сбрасывает введенные данные (Report, Date).
* **History:** Состояние надежно кодируется в URL (hash + query string). Кнопки Back/Forward работают корректно без дополнительных пушей в историю (isPopping флаг). В P207 кнопки Simulate теперь недоступны.
* **Timeline Evidence:** Вместо абстрактных точек на десктопе теперь выводятся конкретные критерии для достижения RFT (100% trace, визуальный осмотр, статус NDE) и прямая ссылка на связанный Test Pack.
* **Mobile:** Добавлен overflow-x clamp на уровне body, инпуты на мобильных устройствах теперь имеют `font-size: 16px` для предотвращения автозума в iOS.
