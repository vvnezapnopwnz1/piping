# Отчёт: Концепция B (Process navigator)

## Суть модели
Отказ от единой глобальной боковой панели-каталога в пользу постоянной процессной навигации (Stage Rail). Навигация отражает реальный производственный цикл (Engineering → Fabrication → Erection → Test Packs), а утилиты (NDE, Tracking) выведены в раздел общих сервисов. Основной экран (overview) работает не просто как дашборд, а как пространственная, интерактивная процессная карта с конкретными показателями (work counters) и прямыми точками входа в операции. Очередь заблокированных объектов (Blocked Objects Action Queue) позволяет инженеру сразу переходить к узким местам без поиска по таблицам. Внутри конкретной стадии или задачи, пространственная карта сжимается в компактную навигационную панель сверху, освобождая максимум места, а под ней появляется локальная навигация (Local Nav) для конкретного этапа. 

Вся навигационная структура (карта, рельс, локальные табы) строится из единого реестра `NAV_REGISTRY`, обеспечивая целостность.

Контекстная помощь реализована в виде coach mark — немодального popover-окна со стрелкой, которое вызывается по клику на иконку вопроса. Встроена поддержка отключения советов (Don't suggest again), сохранения предпочтений в LocalStorage и закрытия по Esc.

## Преимущества (Pros)
- **Ментальная модель:** Интерфейс совпадает с реальным физическим процессом на площадке, обучая пользователя порядку производственного цикла.
- **Освобождение пространства:** Отсутствие постоянного левого сайдбара даёт больше места по ширине для сложных таблиц, матриц и логов.
- **Ориентация:** Пользователь всегда видит свое место в глобальном процессе на Stage Rail, при этом не отвлекаясь на ссылки из совершенно других стадий.
- **Ясность блокировок и действий:** Вместо текстов под таблицами, помощь привязана к конкретным полям. Очередь действий на Overview сразу направляет инженера к решению проблем (например, открытых obligations NDE).
- **Ролевая адаптация:** Плавное изменение UI для пользователей только с правами чтения (Reader), что предотвращает случайные ошибки и скрывает ненужный интерфейс.

## Компромиссы (Tradeoffs)
- **Доступ к удалённым разделам:** Переход из Fabrication сразу в Test Packs требует клика по рельсу, что может быть непривычно для тех, кто привык видеть всё дерево ссылок постоянно (как в традиционных сайдбарах).
- **Иерархия:** Сложно вписать модули, которые не ложатся в прямой физический цикл (например, настройки, отчеты, импорт данных) — они требуют выноса в отдельное глобальное меню приложения или профиль.

## Реализованные взаимодействия
1. **Единый реестр маршрутов:** Переключение экранов, отрисовка Process Map, Stage Rail и Local Nav осуществляются на основе `NAV_REGISTRY`. В URL используется hash-роутинг с поддержкой истории (`#project=P-104&view=overview&spool=SP-1001-A`), что позволяет использовать кнопки Back/Forward браузера.
2. **Переключение проектов (Projects → Overview):** Смена проекта (P-104 или P-207) с полной очисткой данных (в P-207 пустой список). Присутствует Sticky Identity Band со сменой роли QC Engineer / Reader.
3. **Режим чтения (Reader Role):** Навигация (OpenProject, Return, поиск, фильтры, Open/Resolve) не скрывается и не блокируется. Только write-кнопки `[data-action="simulate-save"]` получают реальный `disabled`, а поля Material/NDE (`.trace-input`, `#nde-form`) — `disabled`+`readonly`; рядом показывается пояснение read-only. Защита в обработчике `simulate-save` сохранена. При возврате в QC кнопки включаются только на валидной стадии (`isWriteStageValid`): Start Testing/Record Blinding остаётся заблокированным, пока NDE не закрыт.

   Правка Reader (точечная): удалено CSS-правило `body.role-reader .btn.primary {display:none}` и `pointer-events:none` на всех input в main; добавлена `applyRoleState()` в `app.js` (вызывается в конце `render()` и `simulateSave()`).
4. **Очередь задач:** На Overview отображаются Actionable items (нехватка данных в Material, открытый NDE), по клику на "Resolve" происходит прямой переход к конкретному Spool на нужной стадии.
5. **Фильтрация Fabrication:** Таблица Fabrication детально расписана, работает текстовый поиск по Spool/ISO/Location. Есть состояния no matches и empty project, а также кнопка очистки.
6. **Контекстная помощь:** Coach Mark реализован для каждой важной точки с пояснениями. Закрывается по кнопке «Close», по клавише «Esc» и по смене экрана. Состояние «Don't suggest again» сохраняется в localStorage.
7. **Симуляция рабочего процесса (Simulate Save):**
   - На Material Check происходит валидация пустых полей. Сохраняется реальный введенный код Heat Trace.
   - В NDE Workspace обязательны Report Date, Outcome и Report Number. При выборе Rejected обязательно указание Defect Code. Rejected сохраняет блокер, Accepted — снимает.
   - На экране Ready for Test (RFT) при переходе из NDE видно, что блокер пропал (0 NDE obligations open), и статус изменился на "Ready for Test Pack Allocation".
   - На Test Pack TP-014 статус обновляется в соответствии с RFT, разблокируется действие "Record Blinding", а затем "Start Testing".
8. **Ограничения Scope:** Engineering, Tracking, Dashboard (Fabrication/Erection) визуально отключены (`disabled`) и помечены `Outside this prototype`.

## Правка B по screenshot (4 точечных исправления)
- Overview: плашка `NDE Service` больше не `absolute` и не перекрывает карточку Erection — она отдельной нижней строкой под stage-картами, соединена dashed-линией; на mobile одна колонка без overflow.
- Overview-счётчик Ready for Test (только агрегат проекта): 1 изначально, 2 после Accepted. Gate выбранного spool (RFT) не менялся.
- Счётчики NDE (Obligations/Recorded/Awaiting): добавлен gap между подписью и значением, текст не склеивается.
- Ссылка Review в тёмном баннере: светлый цвет + underline вместо низкоконтрастного sage.

## Созданные файлы
- `index.html` — единая структура приложения с детальной разметкой, Identity Band, формами и валидацией.
- `styles.css` — эстетика "диаграмма/редактор", теплая бумага (#f5ead8), сетка, акцентные Charcoal и Terracotta. Полная адаптивность для Mobile (390px) и Desktop. Поддержка стилей Reader mode.
- `app.js` — роутинг на основе URL hash, управление состоянием (State), продвинутая валидация форм, управление контекстной помощью (LocalStorage), парсинг `NAV_REGISTRY`.
- `report.md` — описание концепции и реализации второго прохода.
