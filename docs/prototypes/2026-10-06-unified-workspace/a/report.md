# Отчёт о разработке прототипа UX (Концепция A - Детализированная версия)

## Суть модели
Концепция A представляет собой единое рабочее пространство (Workspace) с компактной боковой панелью, которая служит постоянной и единственной глобальной навигацией. Навигационная модель использует единый реестр состояний. Обзор проекта (Overview) работает как операционная панель с метриками и прямой рабочей очередью, обеспечивая быстрый доступ к приоритетным задачам без промежуточных экранов и независимых карт процессов.

## Преимущества
- **Единый контекст:** Пользователь всегда понимает, в каком проекте находится, благодаря тёмной ленте идентификации (Identity Band) на всех экранах.
- **Ориентация на задачи:** Priority Work Queue на главной странице выводит требующие внимания спулы (например, SP-1001-A с блокером NDE) и тестовые пакеты (TP-014), позволяя инженеру сразу приступить к работе.
- **Строгое разделение доступа (Roles):** Интегрирована роль Reader, при выборе которой отключаются все поля ввода и действия, сохраняя только возможность чтения и навигации.
- **Контекстная помощь (Coach marks):** Справка привязана к конкретным рабочим действиям, показывает только уместную информацию для текущего контекста. Поддерживается отключение подсказок, масштабирование на мобильных устройствах и закрытие по ESC.
- **Изолированность проектов:** При переходе на пустой проект (P-207) состояние полностью очищается, исключая просачивание данных из P-104.

## Компромиссы (Trade-offs)
- Размещение всех деталей объекта (Material Check, RFT, Test Pack) на отдельных экранах требует большего количества переходов ("кликов") по сравнению с огромными формами, но "хлебные крошки" (breadcrumbs) упрощают возврат к контексту.
- На малых экранах боковая панель переносится в верхнюю часть экрана (в данной реализации без "гамбургера" для наглядности), что удлиняет скролл, но в B2B-средах десктоп является приоритетным.

## Выполненные взаимодействия и логика
1. **Сквозная навигация (Unified NAV):** Единый роутинг на основе Hash API (`#P-104/nde/SP-1001-A`). Корректная поддержка кнопок Back/Forward в браузере. Восстановление проекта при навигации.
2. **Переключение проектов:** Выбор P-207 переключает контекст на пустой проект. Все представления, включая Overview, корректно показывают Empty State без данных. При возврате на P-104 сбрасываются локальные изменения и восстанавливаются исходные метрики (Reset).
3. **Фильтрация и пустые состояния (Fabrication):** Поиск по Spool ID корректно работает. Состояние "не найдено" при поиске визуально отличается от состояния "пустой проект".
4. **Материальный контроль (Material Check):** Readiness Gate проверяет заполненность всех полей Trace. Попытка симуляции сохранения пустого/неполного Trace не разблокирует статус (выводит ошибку).
5. **Разрешение блокировок (NDE -> RFT -> TestPack):**
   - **NDE:** Результат *Rejected* обязательно требует ввода кода дефекта (Defect Code) и не разблокирует RFT. Сохранение *Accepted* обновляет метрики проекта (19->18, 63->64), снимает блокер со спула SP-1001-A и автоматически обновляет Readiness Gate на экране RFT.
   - **Test Pack:** Только после того, как SP-1001-A переходит в статус Ready for Test, кнопка "Simulate Mark Blinded" для TP-014 становится доступной. Нажатие переводит TP-014 в состояние *Start testing*.
6. **Роль Reader:** Глобальный селектор ролей моментально отключает доступ к интерактивным элементам и формам, информируя об этом предупреждением в Sidebar-е.
7. **Безопасность UI (Контраст и доступность):** Добавлена видимая индикация фокуса (`:focus-visible`), хлебные крошки стали кнопками, поля имеют привязанные лейблы. 

## Созданные файлы
- `index.html` — единый каркас (shell) с внедрённым Identity Band, Breadcrumbs и детализированными рабочими карточками.
- `styles.css` — детальные стили без внешних библиотек (grid 22px, типографика Georgia/sans-serif, responsive 1440/390px, корректные hover/focus-states).
- `app.js` — локальное управление состоянием (State Machine, валидация полей NDE/Material, Hash-маршрутизация), без `eval` и inline-обработчиков.
- `report.md` — этот документ.

2. **Плотность Overview (3 компактные панели):**
   - Overview реструктурирован в 3 компактные равные по высоте панели на десктопе (Fabrication Readiness, NDE Metrics, Priority Work Queue).
   - Числовые показатели скомпонованы в плотную сетку ячеек (`.metrics-tight-grid`).

   - Навигационная модель А (Sidebar как единственный глобальный навигатор) строго сохранена.
3. **Гарды ролей и изоляция данных P-207:**
   - Функции сохранения (`saveMaterial`, `saveNde`, `saveTestPack`) получили строгие проверки на роль (`reader`) и проект (`state.project === 'P-104'`).
   - При переключении на P-207 скрываются все открытые формы (`#nde-form-section`), очищаются все поля ввода Trace и NDE. Старые данные P-104 полностью исключены из DOM.
4. **Валидация NDE и сохранение блокера при Rejected:**
   - Реализована строгая валидация обязательности Report Number, Examination Date, Outcome.

5. **Проверка синтаксиса:**
   - Выполнена проверка синтаксиса `node --check app.js` — код валиден, без предупреждений и ошибок.
