# Окно «Загрузки» для импорта Excel — дизайн (отложено)

Дата 2026-10-23. Ветка `feat/unified-workspace`. **Статус: отложено владельцем 2026-10-23.** Описание согласовано в разговоре, к реализации не принято, плана нет.

## 1. Зачем

Человек загрузил книгу Excel вчера, а сегодня вернулся, чтобы её применить. Сейчас вчерашнюю загрузку на экране импорта не найти: результат проверки хранится только в памяти страницы. В истории (Администрирование → Импорт) такую загрузку можно только отменить или скачать её исходный файл.

## 2. Почему отложено и когда вернуться

Сейчас есть обходной путь: загрузить ту же книгу ещё раз (исходный файл скачивается из истории). Повторная загрузка и есть свежая проверка по сегодняшним справочникам. Объём работы средний: изменение базы, новое окно, переделка плитки и ручной выпуск миграций на demo и app. Пока нет людей, которые возвращаются к загрузке через день, он не окупается.

**Вернуться**, когда реальный пользователь или пилотный заказчик попросит вернуться к загрузке позже, или пожалуется, что книгу приходится загружать заново.

## 3. О чём договорились

### Плитка Excel

Три кнопки: «Скачать шаблон Excel», «Загрузить заполненный шаблон», «Загрузки». Когда проверка заканчивается, само открывается окно «Загрузки» на деталях этой загрузки. Под плитками ошибки и решения по ревизиям больше не выводятся. Окно открывается и кнопкой «Загрузки».

Книгу без листа weld или без обязательной колонки браузер не отправляет, загрузка не создаётся, и причина остаётся на странице, как сейчас *(решение Claude)*.

### Список загрузок

Excel-загрузки проекта от всех людей, новые сверху. Колонки: когда загружено, файл, кто загрузил, сколько изометрий, ошибки, предупреждения, статус, стрелка «детали». Ошибки и предупреждения в списке показаны на момент последней проверки.

Статусы: «Проверен», «Применён», «Отменён». Владелец выбрал «Применён» и «Отменён», а не «Загружено»: «Загружен» уже означает «файл принят, но не проверен». Сломанные загрузки показываются со статусом «Ошибка» *(решение Claude)*.

### Детали загрузки

- Вверху «← Все загрузки», файл, дата, кто загрузил, статус.
- Загрузка со статусом «Проверен» при открытии перепроверяется по сегодняшним справочникам. Пока идёт проверка, показано «Перепроверяем…», кнопки выключены.
- Если есть более новая загрузка тех же изометрий, показывается предупреждение (владелец). Учитываются загрузки из любого источника, кроме отменённых *(решение Claude)*. Это только предупреждение: «Применить» остаётся доступной *(решение Claude)*.
- Ошибки и предупреждения выводятся тем же списком, что сейчас: по причине, с листом, колонкой и строками Excel.
- Ниже блок «Решения по ревизиям», тот же, что сейчас: без решений по изменённым стыкам «Применить» не сработает *(решение Claude)*.
- Кнопки «Отменить» и «Применить». «Применить» работает, только если ошибок нет и все решения приняты, как сейчас. После нажатия любой из кнопок статус меняется на «Применён» или «Отменён», и обе кнопки выключаются (владелец).
- Применённые и отменённые загрузки не перепроверяются: показывается сохранённый результат *(решение Claude)*.

## 4. Не цели

- SpoolGen и PCF не трогать: у каждой плитки свой порядок импорта, владелец сказал «я бы не спешил». Их загрузки в окне не показываются.
- Не загружать файл повторно из окна. Если правило толщины добавили после загрузки, перепроверка скажет «проверьте файлы снова», и человек загружает книгу заново.
- Историю в Администрирование → Импорт не менять.

## 5. Что есть сейчас (на 2026-10-23)

- Задание, все замечания (браузерные и серверные), исходный файл и решения по ревизиям хранятся в базе. Есть и отмена, и применение.
- Перепроверка: `revalidate_spooling_import_job(target_job_id)`, последняя версия в `supabase/migrations/20261021100000_spooling_thickness_frozen_at_validation.sql`. Она пересчитывает только серверные замечания `SRV_*`, браузерные (пустые и нечисловые ячейки) остаются как были. Толщина берётся из правила один раз, при первой проверке; если правило добавили позже, сервер выдаёт второй вариант `SRV_THICKNESS_MISSING` с текстом «check the files again».
- Отмена: RPC `cancel_import_job`, сейчас её вызывает `modules/imports/ui/import-history.tsx`. Решения по ревизиям и применение находятся в `modules/engineering/ui/revision-workbench.tsx`.
- Лист и строки Excel для серверных замечаний сейчас берутся из памяти экрана: `buildIssueEntries(submission, stored)` в `modules/engineering/application/issue-entries.ts` читает `submission.rowSources`. После перезагрузки страницы этой связи нет.
- Источник загрузки (Excel, SpoolGen или PCF) в задании не записан: `create_spooling_import_job` пишет `import_type = 'spooling_definition'`. Определить его можно только по файлам: роль `pcf` значит PCF, один файл `weld` в формате `.xlsx` значит Excel, текстовые файлы значат SpoolGen.

## 6. Что пришлось бы менять

Это решения Claude, подробно они не обсуждались.

- **База.** При записи проверки сохранять для каждой строки staging, из каких листов и строк книги она взята. Для списка добавить одну view `with (security_invoker = true)`: счётчики, кто загрузил, флаг более новой загрузки. Хранить ли источник загрузки явно или выводить его из файлов, решается при планировании. Формат `record_spooling_validation` меняется сразу у всех вызывающих (правило 3 в `CLAUDE.md`).
- **Старые загрузки**, сделанные до изменения, показывают замечания без листа и строк.
- **Экран.** Окно со списком и деталями использует готовые `IssueEntryList` и блок решений по ревизиям. Переделываются плитка Excel (`modules/engineering/ui/excel-import-panel.tsx`) и страница `app/spooling/import/page.tsx`.
- **Выпуск.** Миграции на demo и app применяются вручную, до выпуска образа приложения (`docs/runbooks/hosted-stand-operations.md`).
