# PipeQC — инвесторская презентация (PPTX), 2026-09-04

## Что это и для кого

Дека для инвестора, которую **читают без докладчика**: файл присылают, его открывают и
пересылают партнёрам. Отсюда два следствия для формы: каждый заголовок — утверждение, а не
название раздела, и каждый слайд должен читаться сам по себе.

Язык слайдов — русский. Названия сущностей и экранов остаются английскими, как в интерфейсе
(spool, testpack, WPS, NDE, RFT, PDS area) — это отраслевая терминология, переводить её вредно.

## Решения, принятые до сборки

**Никаких выдуманных метрик.** Ни денег, ни процентов рынка, ни «экономии X часов». Причина не
только этическая: цифры в `roadmap_v3.md`, `gapmap_and_roadmap.md` и `MANUAL_COVERAGE_MATRIX.md`
описывают ещё Zustand-эпоху, до перехода на Supabase, и в слайдах были бы враньём.

**Дека держится на бизнес-логике и экранах**, а не на рынке. Инвестор в этом варианте покупает
очевидность того, что продукт настоящий, и понимание предметной области, которого нет у стороннего
человека. Глубина домена работает как доказательство защитимости, а не как контент сам по себе.

**Ключевой слайд — каскад отклонённого стыка.** Это «единица ценности» продукта: один брак на
рентгене сам порождает ремонтный стык и трассеры, без переписки между участниками. Он показан не
иллюстрацией, а двумя настоящими экранами (см. ниже).

Слайды 5–10 — блок для читателя, который никогда не был на стройке: что такое изометрия и spool,
почему трубу режут на куски, что происходит в цеху, зачем просвечивают шов, чем полевой стык
отличается от цехового и почему испытывают пакет линий, а не трубу. У каждого такого слайда сверху
полоска семи стадий с подсветкой текущей, чтобы читатель не терял место в цепочке. Фактура взята из
`docs/pipeline_construction_guide.md`, а не придумана.

Слайды каскада — смысловой центр. Всё остальное подводит к ним и от них расходится.

## Скриншоты

Снимаются скриптом, не руками: `npm run deck:screens` (`scripts/capture-deck-screenshots.ts`).
1920×1080 при `deviceScaleFactor: 2` — ровно 16:9, как слайд, и текст таблиц читается при печати.
Список кадров живёт в самом скрипте и является контрактом с декой: у каждого кадра указано, на
каком проекте он снимается и какому слайду служит.

Порядок сборки стенда:

```zsh
npm run demo:prepare -- --confirm-local-reset
npm run verify          # до showcase — pgTAP считает пустой стенд
npm run demo:showcase
npm run deck:cascade    # один отклонённый результат, чтобы слайд каскада был настоящим
npm run deck:screens
```

`deck:cascade` (`scripts/seed-deck-cascade.ts`) отклоняет один стык через настоящий UI и позволяет
серверному каскаду отработать. Он меняет данные, поэтому вынесен из `deck:screens` и запускается
один раз после посева.

## Известные пробелы — и что с ними сделано

**Hosted-стенд не годится для съёмки.** Приложение на Vercel отдаёт 200, но его Supabase-проект не
резолвится в DNS: вход падает с «Failed to fetch». Снимали с локального стенда. Публичная ссылка
сейчас нерабочая для любого посетителя — чинить отдельно от презентации.

**Tracking нечего показать.** `spool_location_events` пуст во всех проектах, дашборд перемещений
рендерится пустым. Модуль упоминается на карте системы, но своего слайда не получает.

**Вкладка General в Test Pack Explorer показывает сырые UUID** вместо названий системы, подсистемы
и класса среды. На слайд взята вкладка Release Tracking. Сам дефект остаётся в приложении.

**Экран импорта пустой по замыслу.** `TRACK01-A` стартует без данных, потому что импорт делается
живьём. Слайд показывает форму загрузки, а не результат валидации.
