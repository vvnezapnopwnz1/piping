# Второй демо-проект: НПС (обвязка насосной)

Дата: 2026-10-20. Решения владельца: на публичном демо (`https://demo.piping-qc-work.shop`) лежат образцы проектов;
первый — UPG-1 (загружен, 8 недель), второй — «НПС: обвязка насосной», **до недели 5** из 8 (проект «в работе»).
Данные синтетические: открытого образца нет, формат PCF не публичный. Состав ниже — наша оценка, не источник.

## Порядок

1. **T1. Параметризация генератора, без смены поведения.** `scripts/upg/*` написан под UPG-1: `UPG_ISOS`, `ISO_GROUPS`,
   `SERVICE_CLASSES` и другие константы модуля импортируют 15 файлов. Нужен один объект-описание проекта
   (`ProjectSpec`) и построители, которые его принимают. Критерий готовности: `npm run demo:project-files`
   перегенерирует `fixtures/demo-project/` и `git diff fixtures/` пуст; unit-тесты зелёные.
2. **T2. Описание НПС** (`scripts/nps/dataset.ts` или рядом): тот же `ProjectSpec`, состав ниже; пока только данные, файлы
   SpoolGen не пишем (формат уточняется в соседней сессии).
3. **T3. Справочники и Excel-импорты 01–06 НПС на демо.**
4. **T4 (после решения по формату спулинга).** Четыре файла SpoolGen, импорт, прогон недель 1–5, проверка документов.

## T1. Форма параметризации

- `ProjectSpec` собирает то, что сейчас зашито: `project` (код, название, заказчик, подрядчик, договор, транзит),
  `shopSubcontractor`/`fieldSubcontractor`, `lineServices`, `serviceClasses`, `systems`, `pdsAreas`, `isoGroups`,
  `welders`, `weldingProcedures` (`wps`), `ndeImportRules`, `pwhtFormRules`, `pwhtThresholdMm`, префикс номера ISO,
  особые случаи (`threadIsos`, `revisionIso`, `rejectWeld`, `wpsGapIso`, `errorIso`, `overdueSpool`; у НПС часть может
  быть `null`), `packScenario` (список действий по пакетам).
- Построители (`buildIsos`, `revisionR1`, `errorIso`, `materialLines`, `weldsFor`, `spoolsFor`) переезжают в
  `scripts/upg/builders.ts` и принимают спецификацию. `dataset.ts` остаётся данными UPG-1 и экспортирует `UPG_SPEC`.
- `files.ts`, `weeks.ts`, `references.ts`, `execute.ts`, `load-project.ts`, `run-week.ts`, `setup-references.ts`,
  `write-files.ts` получают спецификацию аргументом. CLI выбирает проект флагом `--dataset upg|nps` (по умолчанию
  `upg`: это существующая команда, а не запасной вариант старого формата).
- Фикстуры: `fixtures/demo-project` остаётся каталогом UPG-1; для НПС — `fixtures/demo-project-nps`.
- Тесты: существующие тесты переводятся на `UPG_SPEC`; ни один не ослабляется.

## T2. Состав НПС (оценка)

| Что | Значение |
|---|---|
| Проект | `NPS-1`, «Насосная станция НПС-1, обвязка», заказчик ТОО «Демо Трубопровод», подрядчик ТОО «Демо Монтаж» |
| ISO / катушки / стыки | ≈36 / ≈100 / ≈380; цеховых ≈70%, полевых ≈30%; типы BW, SW (дренажи, импульсные), FW. Фактически по формулам построителей (общим с UPG-1): 36 / 84 / 516, цеховых 84%, полевых 16% (по одному полевому стыку на катушку) |
| Классы | CS150 (дренажи, утилиты), CS300 (всасывание), CS300H (нагнетание: 300#, толстая стенка, PWHT от 19 мм). Класс CS600 из первой редакции заменён на CS300H: в приложении рейтинги фланцев только 150# и 300#, правил UT и таблиц затяжки для 600# нет |
| Диаметры | 2–24"; основные: CS300 16, 20, 24; CS300H 12, 16, 20; CS150 3–8 |
| Системы | 100 всасывание, 200 нагнетание (насосы Н-1/2/3), 300 узел СОД и дренажи |
| Тест-пакеты | 8, по давлению и классу |
| NDE | 100% RT на CS300H (стыковые, цех и поле; через форму, в импорте матрицы нет колонок PWHT) и 100% MT на её SW, остальное по матрице; PWHT от 19 мм |
| Недели | 1–5; когорты как в UPG-1: A завершает, B готова к испытанию, C на монтаже, D в цеху |
| Особые случаи | брак в первом цеховом NDE, ревизия R1 в цеху, одна просроченная катушка (замыкающих катушек в генераторе нет) |

Пробное давление, толщины стенок CS300H и процент NDE — по ГОСТ 32569-2013 (табл. 12.3, проверено) и ASME B36.10/B16.5; значения,
которых нет в проверенных источниках, помечаются в коде комментарием `// оценка`.
