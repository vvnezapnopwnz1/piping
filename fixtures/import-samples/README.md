# Образцы файлов для импорта (PCF)

Файлы **синтетические**: написаны вручную, не выгружены ни из одной системы и не содержат данных заказчика. Они
повторяют раскладку и набор ключевых слов реальных выгрузок, чтобы каждая плитка экрана «Импорт» прошла весь путь
от файла до строк предпросмотра. Проверяет их `modules/engineering/application/import-samples.test.ts`:

```zsh
node --import tsx --test modules/engineering/application/import-samples.test.ts
```

Тест читает файлы так же, как экран (`decodeText`, `buildPcfSubmission`),
держит каждое выведенное значение и для основных правил убирает одну входную деталь, чтобы убедиться, что образец
действительно проверяет своё правило.

Линии названы в стиле проекта UPG-1 (`4-NG-1001-CS150`), классы `CS150` и `CS300` есть в справочниках UPG-1, зону PDS
(`A-100` в UPG-1) PCF не содержит: её выбирают на экране один раз для всей загрузки. Образцы показывают и проверяют
в браузере **до шага предпросмотра, их не применяют**, и не на `TRACK01-A`, `TRACK01-B` и `SHOWCASE-1`.

## Что взято откуда

| Образец | Имитирует | На чём основан |
|---|---|---|
| `aveva/ISO-1001.pcf`, `aveva/ISO-1002.pcf` | выгрузку PCF из AVEVA E3D / PDMS (Isodraft) | Раскладка из Hexagon *Piping Component File Reference Guide* (формат PCF общий для Isogen-совместимых систем): шапка `ISOGEN-FILES` и `UNITS-*`, затем `PIPELINE-REFERENCE` с отступом атрибутов в 4 пробела, ключевое слово компонента в колонке 1, `MATERIALS` в конце. |
| `hexagon/ISO-2001.pcf` | выгрузку Intergraph Smart 3D / CADWorx | Та же раскладка, что у Hexagon PCF Reference Guide, плюс `UCI`, `WELD-TYPE` и `CATEGORY` у стыка, как в задании шаблонов импорта. |
| `plant3d/ISO-3001.pcf` | выгрузку Autodesk Plant 3D (Isogen PCF) | Раскладка, которую разбирает читатель PCF (`parsers/pcf.ts`): атрибуты трубопровода в колонке 1, атрибуты компонентов с табуляцией, строки через CRLF, диаметры в дюймах. Автодеск такую раскладку открыто не публикует. |

Что подтверждено по открытым источникам: раскладка PCF взята из выдержки из Hexagon PCF Reference Guide, на которой
написан `parsers/pcf.test.ts` (само руководство при составлении образцов не открывалось); в документации PTC Creo (*Weld Information in PCF Files*) `REPEAT-WELD-IDENTIFIER`
назван номером стыка, а `SKEY` типом. Что **не** удалось сверить с первоисточником и взято из грамматики, которую
читает код (`parsers/pcf.ts`, `pcf-welds.ts`): `MASTER-COMPONENT-IDENTIFIER`, `WELD-TYPE` и `CATEGORY` у стыка,
`UNITS-BORE INCH-SIXTEENTH`, а также точные значения `SKEY` (`FLWN`, `ELBW`, `RCBW`, `TEBW`, `ELSW`, `TESW`). Перед
показом заказчику образцы стоит сверить с настоящим файлом его системы: расхождение покажет, какие правила чтения нужно
поправить.

## Что проверяет каждый образец и что должно получиться

Изометрия берётся из имени файла, зона PDS `A-100` выбрана на экране, толщина стенки в PCF пуста (её заполняет сервер).

**`aveva/ISO-1001.pcf`** (мм, `SPOOL-IDENTIFIER`, явные `WELD`, `MASTER-COMPONENT-IDENTIFIER`, `SKEY WW` и `WS`, без `WELD-TYPE`).
Ревизия `B`, класс `CS150`, линия `6-NG-1001-CS150`. 8 стыков, 3 катушки (`1001-SP01..03`), без замечаний. Тип стыка
`BW` везде: он берётся из конца детали в точке стыка. Диаметры 6, 6, 6, 6, 4, 4, 4, 4: DN150 и DN100 по таблице, на
малом конце переходника диаметр берётся с самого стыка. Монтажные (`WS`): стыки 3 и 6. Стык 3 записан после трубы
следующей катушки, и в катушку `1001-SP01` его возвращает только мастер-компонент.

**`aveva/ISO-1002.pcf`** (без `SPOOL-IDENTIFIER` и без мастер-компонентов).
Ревизия `0`, линия `4-NG-1002-CS150`. 4 стыка, одна катушка с именем файла `ISO-1002` и одно предупреждение
`PCF_SPOOL_FROM_FILE_NAME`. Деталь стыка берётся ближайшая выше по файлу. Стык 4 стоит на отводе тройника (DN50): его
диаметр 2 берётся с самого стыка, а тип `BW` с окончания `SKEY` тройника (`TEBW`), потому что отвод не конец `END-POINT`.

**`hexagon/ISO-2001.pcf`** (`UCI`, `WELD-TYPE BW` и `SW`, `CATEGORY`, диаметры в 1/16 дюйма).
Ревизия `A`, класс `CS300`, линия `2-NG-2001-CS300`. 5 стыков, 2 катушки (`2001-S1`, `2001-S2`), без замечаний. Типы
`BW, SW, SW, SW, SW`; место сварки берётся из `CATEGORY` (у стыков нет `SKEY`): монтажный только стык 3 (`ERECTION`).
Диаметры 2, 2, 2, 2 и **0.75** (отвод 12/16 дюйма). `WELD-TYPE` здесь нужен: без него тип стыка у гладкого конца трубы (`PL`) вышел бы `PL`.

**`plant3d/ISO-3001.pcf`** (дюймы, атрибуты трубопровода в колонке 1, табуляция, CRLF).
Ревизия `2`, класс `CS150`, линия `6-NG-3001-CS150`. 6 стыков, 2 катушки (`3001-1`, `3001-2`), без замечаний. У концов
деталей нет типа, поэтому тип берётся с конца `SKEY` детали: `FLWN` даёт `WN`, а шаблон превращает `WN` в `BW`; `ELBW`
и `RCBW` дают `BW` сразу. Стык записан раньше своей детали, и её даёт `MASTER-COMPONENT-IDENTIFIER`. Диаметры 6, 6, 6,
6, 4, 4. Монтажный (`WF`) только стык 3.

**Все четыре PCF вместе**: 4 изометрии, 8 катушек, 23 стыка, 35 строк, одно предупреждение (ISO-1002), любой порядок
файлов даёт те же строки.

## Как менять образцы

- `plant3d/ISO-3001.pcf` хранится с табуляциями и CRLF: не форматируйте его редактором, который заменяет табуляции пробелами.
- Значения для каждого файла записаны в тесте таблицами. Изменили образец: поправьте таблицу и этот файл.

## Чем скачанный шаблон отличается от образцов в этой папке

Образцы в этой папке — то, что **читает** импорт: выгрузки систем проектирования. Их проверяет `modules/engineering/application/import-samples.test.ts`.

Шаблоны, которые экран отдаёт кнопками на плитках, собираются в коде и в папке не лежат:

- Excel — `modules/engineering/infrastructure/import-template-data.ts` (какие колонки и что в них) и
  `modules/engineering/ui/import-template-sheets.ts` (листы «Справка» и «Коды проекта»);
- SpoolGen — тот же файл данных плюс `modules/engineering/infrastructure/import-template-files.ts`;
- PCF — `modules/engineering/infrastructure/pcf-sample.ts`.

Их общее обещание проверяет `modules/engineering/application/import-template-roundtrip.test.ts`: скачанное,
заполненное по строке-примеру, загружается без ошибок и без ручного сопоставления. Свой реестр в его собственном виде
больше не загружается, только через шаблон: тест проверяет, что скачанная книга загружается одним выбором файла. Меняя
образец здесь, сверьтесь с этим тестом: он держит и шаблон, и образцы.
